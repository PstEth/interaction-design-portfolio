Blume Color

Turning visual references into cinematic color grades.

Problem

Color matching is a long, expert loop.

Find reference→ Analyze colors→ Exposure→ Contrast→ Highlights→ Shadows→ Saturation→ Repeat→ Export

Each pass is a judgment call. The traditional workflow is powerful and slow. Most people who know the look they want cannot operate a grading suite fluently enough to reach it.

Solution

A reference-led grade, not a parameter-led one.

Raw video + reference image→ Blume Color→ Automatic color match→ Graded video

Product architecture

Reference image→ Visual analysis→ Color characteristics→ Matching→ Video processing→ Graded output

The diagram describes the intended product logic, not a confirmed implementation. Analysis extracts visual characteristics from the still; matching proposes a grade; the user remains the editor of intensity and export.

Product thinking

Target userEditors and filmmakers who think in references, not in wheels and curves.
ProblemMatching a still to moving image is slow, expert, and iterative.
Value propositionGet to a cinematic match from two files, then tune — don’t start from zero.
Core featureReference-to-video color match with a visible before/after and intensity control.
User flowUpload → match → compare → adjust → export.
Interaction modelThe grade is a proposal. The user remains in control of strength and export.
OutcomeA shorter path from “this look” to a file they can use.

Reflection

Lesson 01

AI should propose, not finish

Creative tools fail when they hide the result. The match is a starting point; intensity and comparison keep the editor in the loop.

Lesson 02

References are a language

People already brief with stills. The product should speak that language instead of inventing a new control surface.

Lesson 03

Trust is a layout problem

Before/after, processing visibility, and an honest limit on what the system claims mattered more than extra features.
